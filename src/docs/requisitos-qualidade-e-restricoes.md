# Requisitos de Qualidade e Restrições - MiniBlog

## 1. Introdução e objetivo

Este documento apresenta os requisitos não funcionais e as restrições do MiniBlog. Para montar essa documentação, foram consultados o código do front-end, as configurações, as dependências e as histórias de usuário do projeto.

Os requisitos funcionais continuam descritos nas histórias de usuário e no [Documento de Visão](./documento-visao.md). Aqui, o foco é definir como o sistema deve funcionar em relação à qualidade, ao desempenho, à segurança e a outros aspectos.

Também foram definidos critérios para verificar se os requisitos estão sendo atendidos. Isso não significa que todos já foram cumpridos. Quando foi possível verificar a situação atual pelo código, essa informação foi registrada.

### 1.1. Escopo analisado

A análise foi feita no front-end do projeto, desenvolvido com React, TypeScript e Vite. A API foi considerada apenas como parte da integração com o sistema, pois o código do back-end não foi analisado.

| RQ-11 | Os tokens de acesso e atualização não devem aparecer no console ou nas mensagens de erro, nem ser enviados para endereços diferentes da API configurada. ## 3. Verificação dos requisitos

### 3.1. Testes e verificações já realizados

| Verificação                  | Comando ou procedimento                                                | Resultado encontrado                                                                                                                                                         |
| ---------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Compilação do projeto        | `pnpm build`                                                           | O comando falhou com 3 erros de TypeScript: `nomeUsuario`, `testeAuth` e `Comentario` foram declarados, mas não estão sendo utilizados.                                      |
| Análise do código            | `pnpm lint`                                                            | O comando falhou com 28 erros, incluindo uso de `any`, variáveis não utilizadas, problemas de espaçamento e uma violação relacionada à pureza do React.                      |
| Instalação das dependências  | `pnpm install --frozen-lockfile`                                       | Esse comando será usado para conferir se a instalação pode ser repetida com as versões do lockfile. Ele não foi executado para alterar as dependências durante esta análise. |
| Rotas e integração com a API | Análise de `App.tsx`, `PrivateRoute.tsx`, serviços e interceptor Axios | Foram encontradas as rotas `/login`, `/cadastro` e `/home`, além da configuração da API e do envio do token Bearer.                                                          |

### 3.2. Testes que ainda precisam ser feitos

Alguns requisitos ainda precisam de testes para confirmar se estão sendo atendidos:

- Criar testes automatizados para os principais fluxos do sistema.
- Medir o tempo de carregamento das telas e registrar os resultados.
- Testar a acessibilidade com teclado e ferramenta automatizada.
- Conferir o funcionamento em telas de diferentes tamanhos.
- Simular falhas de rede, erros da API e expiração de token.
- Definir quais navegadores serão oficialmente suportados.
- Resolver a diferença entre o limite de 200 e 280 caracteres para os comentários.

### 4.2. Informações que ainda precisam ser definidas

Algumas informações não foram encontradas no repositório. Por isso, elas ainda não foram consideradas restrições obrigatórias do projeto:

- Quais navegadores e versões serão suportados.
- Onde a aplicação será hospedada e como será feita a publicação.
- Qual será a disponibilidade esperada da API.
- Quais tipos e tamanhos de imagem serão aceitos pelo serviço.
- Como será feita a expiração, renovação e revogação dos tokens.
- Qual nível de acessibilidade será adotado, como os critérios da WCAG.
- Como serão organizados os testes automatizados e a integração contínua.
- Quais versões do Node.js e do pnpm serão utilizadas. A documentação antiga menciona o Node.js 18.13.0, mas essa informação precisa ser conferida com as versões atuais do projeto.

Essas informações devem ser definidas pela equipe antes de serem tratadas como regras obrigatórias.

## 5. Uso da ISO/IEC 25010

A ISO/IEC 25010:2023 foi utilizada como referência para organizar os requisitos de qualidade do MiniBlog. Foram consideradas as características mais relacionadas ao projeto:

- Adequação funcional;
- Eficiência de desempenho;
- Compatibilidade;
- Capacidade de interação;
- Confiabilidade;
- Segurança;
- Manutenibilidade;
- Flexibilidade.

Os tempos, percentuais e outros valores definidos neste documento são metas propostas para o MiniBlog. Eles não são valores exigidos pela norma e também não significam que o projeto já atingiu esses resultados.
